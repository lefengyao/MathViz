# 离散数学

## 一、图

```js
var G = MK.graph({
  box:[40,24,600,350], directed:true, layout:"circle",
  nodes:["A","B","C","D","E"],
  edges:[["A","B",4], ["A","C",2], ["B","C",1]]
});
document.getElementById("fig").appendChild(G.svg);
G.layout("circle").draw();
```

- 无向图：`directed:false`，箭头不画。
- 边标签：数组第三位 `["A","B",4]` 就是权重，或用对象 `{s:"A", t:"B", label:"4"}`。
- 多重边：同一对节点写多次，运行时会自动弯成不同弧度的曲线。
- 自环：`["A","A"]`，画在节点上方。

### 布局选择

| 图 | 布局 | 说明 |
|---|---|---|
| 抽象图、关系图 | `circle` | 最稳，节点 ≤ 12 |
| 树 / 有根结构 | `tree` | 需给 `root` |
| DAG / 偏序 / 流程 | `layered` | 自动分层 + 重心排序减交叉 |
| 网络、社交图 | `force` | 结果随机，节点多会乱 |
| 邻接演示 | `grid` | 规整 |

**不要对树用 `force`**：父子层级会被打乱，看起来就不像树了。

### 最短路径 / 通路高亮

```js
G.draw();
G.path(["A","C","B","D","E"], { color:"red", w:3 });
```

`path` 沿已有边的实际走向重画（包括绕行曲线），不会穿节点。起点/终点也高亮就用 `G.mark("A", {color:"green"})`。

## 二、树

```js
MK.graph({
  directed:true, layout:"tree", root:"A",
  nodes:["A","B","C","D","E","F","G"],
  edges:[["A","B"],["A","C"],["B","D"],["B","E"],["C","F"],["C","G"]]
});
```

`layoutTree` 用 BFS 定层级，同层均分。**不保证子树居中**：如果一个节点只有一个子节点，子节点会落在该层自己的槽位上，可能偏。要精确控制就手给 `{id:"D", x:120, y:260, fixed:true}`。

## 三、哈斯图（偏序关系）

哈斯图 = 偏序关系的**传递约简**：只画覆盖关系（`a ⋖ b` 表示 `a<b` 且没有 `c` 使 `a<c<b`），且方向隐含为向上，所以**不画箭头**。

```js
MK.graph({
  directed:false, layout:"layered",
  nodes:["∅","{a}","{b}","{c}","{a,b}","{a,c}","{b,c}","{a,b,c}"],
  edges:[["∅","{a}"],["∅","{b}"],["∅","{c}"],
         ["{a}","{a,b}"],["{a}","{a,c}"],["{b}","{a,b}"],["{b}","{b,c}"],
         ["{c}","{a,c}"],["{c}","{b,c}"],
         ["{a,b}","{a,b,c}"],["{a,c}","{a,b,c}"],["{b,c}","{a,b,c}"]]
}).draw();
```

三条铁律：

1. **只画覆盖关系**。`∅ ⊆ {a,b,c}` 虽然成立，但中间有 `{a}`，所以不画这条边。多画一条就是错的。
2. **不画箭头**。垂直位置表示序关系，向上的边就是"小于"。
3. **最小元在最上、最大元在最下**（教材习惯），或反过来——同一张图内保持一致即可。

`layered` 布局默认按入度分层，正好对应偏序的秩。

## 四、等价关系与划分

等价关系 ↔ 集合的划分 ↔ 等价类。图上表现为**若干个互不相连的完全子图**（每个等价类是一个团）。

```js
nodes: ["1","2","3","4","5","6"],
edges: [["1","2"],["1","3"],["2","3"],      // {1,2,3} 一类
        ["4","5"],["4","6"],["5","6"]]      // {4,5,6} 一类
```

画的时候按类分簇（手动给坐标或分组用 `layout:"grid"`），不要用 `force` 把它们搅在一起。

## 五、文氏图

```js
MK.venn({
  box:[40,20,600,300],
  sets:[{label:"A",color:"blue"},{label:"B",color:"coral"},{label:"C",color:"teal"}],
  labels:{ a:"1", b:"2", c:"3", ab:"4", ac:"5", bc:"6", abc:"7" }
});
```

`labels` 的位置由圆心几何算出，**不要自己调 `regions` 偏移**——除非要放具体元素名（`{2,4,6}` 这类）。

两集合时 `labels` 只有 `a/b/ab`。

## 六、关系矩阵 / 邻接矩阵

```js
MK.matrix({
  x:90, y:60, cell:36,
  rows:["a","b","c"], cols:["a","b","c"],
  data:[[1,0,1],[0,1,1],[1,1,0]],
  label:"关系 R 的关系矩阵"
});
```

- 1 的格子自动浅蓝高亮，0 保持空白。
- 矩阵尺寸大时 `cell` 调到 28~30。
- **真值表不要画进 SVG**，用 markdown 表格写在正文里（可复制、窄屏不崩）。

## 七、自动机

```js
MK.graph({
  directed:true, layout:"circle",
  nodes:[
    {id:"q0", label:"q₀", accept:false},
    {id:"q1", label:"q₁", accept:true}
  ],
  edges:[["q0","q0","0"], ["q0","q1","1"], ["q1","q1","0,1"]]
}).draw();
```

- 接受态用 `accept:true` → 双圈。
- 起始态要另加一个从外部指进来的箭头：`G.svg` 画完后补一条

```js
var n = G.nodes[G.ix["q0"]];
var g = MK.mk("g", null, G.svg);
MK.mk("line", {x1:n.x-44, y1:n.y, x2:n.x-G.radius(n)-7, y2:n.y,
               stroke:MK.ink(), "stroke-width":1.4}, g);
MK.mk("path", {d:"M"+(n.x-G.radius(n))+" "+n.y+" l-8 -4 v8 z", fill:MK.ink()}, g);
MK.txt(g, n.x-52, n.y+4, "start", {size:10, fill:MK.ink(), anchor:"end"});
```

- 边标签是输入字符，多个字符用 `"0,1"`。

## 八、逻辑门电路

内置没有门电路，手写 SVG 更可控。三种基本门的路径：

```svg
<g stroke="#185FA5" stroke-width="1.6" fill="#E6F1FB">
  <!-- 与门：直边 + 半圆 -->
  <path d="M0 0 h34 a22 22 0 0 1 0 44 h-34 z"/>
  <!-- 或门：弧形前脸 -->
  <path d="M0 0 q22 22 0 44 q30 0 46 -22 q-16 -22 -46 -22 z"/>
  <!-- 非门：三角 + 小圆 -->
  <path d="M0 0 l40 22 l-40 22 z"/>
  <circle cx="46" cy="22" r="4" fill="none"/>
</g>
```

门的输入线从左侧进、输出线从右侧出，**连线要落在门的端口上，不要悬空**。三个门的尺寸统一（高 44），否则电路看起来歪。

## 九、常见错误

| 现象 | 原因 | 修法 |
|---|---|---|
| 哈斯图多出斜跨的边 | 画了传递边 | 只保留覆盖关系 |
| 树看起来不像树 | 用了 `force` | 改 `tree` |
| 边穿过节点 | 手写坐标没检查 | 用 `MK.graph`，自动避让 |
| 有向图没箭头 | `directed` 写成 `false` | 检查参数 |
| 最短路径高亮断开 | 路径上的边不存在 | `path` 只能沿已有边走 |
| 自环画到节点里 | 半径不够 | 加大 `r` 或减小 `edge` 偏移 |
| 文氏图数字乱 | 手填偏移 | 用 `labels` 预设位置 |
